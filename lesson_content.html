Why this work matters

Protecting wildlife starts with knowing what is there.

Wildlife conservation means protecting wild animals, their habitats, and the relationships that keep ecosystems healthy. Animals disperse seeds, pollinate plants, and play different roles in food webs. Protecting the places they live helps preserve these connections and the forests, wetlands, and other natural spaces that people depend on, too.

These are full camera-trap frames. Captions describe the source photos; open a photo in the lab to inspect the actual AI predictions. The raccoon and coyote sources do not specify exact capture sites.

To protect wildlife, researchers need evidence: Which species use a place? When are they active? Where might a road interrupt their movement? Camera traps automatically take photographs when their sensors are triggered, recording activity without a person standing nearby. They can reveal shy animals and nighttime visitors. Carefully planned surveys, repeated over time, help teams decide where to protect habitat, restore connections between habitats, or investigate a possible change.

A camera can collect photographs much faster than a person can review them.

Cameras can run for weeks or months across many sites. Large projects produce enormous collections, including empty frames, repeated visits, animals, people, and vehicles. Checking every photograph by hand can take longer than a conservation team has available. AI can greatly speed up that first pass by finding likely animals and people, helping sort likely empty scenes, and suggesting animal labels for people to check.

AI makes mistakes, so human review remains part of the work. A person detection marks someone's presence and location; it does not establish their identity. Repeated photographs of one animal also do not tell us how many different animals live there.

So how does a computer turn a photograph into an animal prediction? That is a computer vision problem. Next, explore the pixels, Python code, and training steps that make it possible.

02 · Turn a photograph into numbers

A tiny moving window can respond to an edge.

A color image usually has red, green, and blue values at every pixel. A convolution combines a small neighborhood with weights, adds a bias, and repeats the same operation across the image. Stacking learned operations lets later layers combine information from larger regions.

How is this related to a real neural network?

Here we choose a simple edge or averaging filter ourselves. In a trained convolutional network, many weights are adjusted from examples. A filter can combine several input channels, and its response can feed activations such as ReLU. Real features are distributed across many channels and layers; they are not a tidy list of rules such as “this neuron means ear.” Modern detectors combine feature maps at different scales and use additional prediction layers.

Resizing, normalization, channel order, and padding must match the trained model. This lab letterboxes MegaDetector inputs to 640 × 640. It separately prepares SpeciesNet crops for its pinned 480 × 480 input process. These are two different models with two different preprocessing contracts.

In a separate training project, prepare my_training_data/train/CLASS_NAME/, val/CLASS_NAME/, and test/CLASS_NAME/ with the same class folders in all splits. Split the encounters and camera sites yourself first; these folders do not create an independent split automatically. Supply real checked photographs. The example uses the installed PyTorch and torchvision APIs; it downloads no data or weights.

from copy import deepcopy
from pathlib import Path
import torch
from torch import nn
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

torch.manual_seed(7)
root = Path("my_training_data")
train_transform = transforms.Compose([
    transforms.Resize((96, 96)),
    transforms.RandomHorizontalFlip(),
    transforms.ToTensor(),  # RGB pixels: [0, 255] to [0, 1]
])
eval_transform = transforms.Compose([
    transforms.Resize((96, 96)), transforms.ToTensor()
])
train_ds = datasets.ImageFolder(root / "train", train_transform)
val_ds = datasets.ImageFolder(root / "val", eval_transform)
test_ds = datasets.ImageFolder(root / "test", eval_transform)
assert train_ds.class_to_idx == val_ds.class_to_idx == test_ds.class_to_idx
train_loader = DataLoader(train_ds, batch_size=16, shuffle=True,
                          num_workers=0)
val_loader = DataLoader(val_ds, batch_size=16, num_workers=0)
test_loader = DataLoader(test_ds, batch_size=16, num_workers=0)

class TinyClassifier(nn.Module):
    def __init__(self, number_of_classes):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(3, 16, kernel_size=3, padding=1), nn.ReLU(),
            nn.MaxPool2d(2),
            nn.Conv2d(16, 32, kernel_size=3, padding=1), nn.ReLU(),
            nn.MaxPool2d(2),
            nn.Conv2d(32, 64, kernel_size=3, padding=1), nn.ReLU(),
            nn.AdaptiveAvgPool2d((1, 1)),
        )
        self.head = nn.Linear(64, number_of_classes)

    def forward(self, images):
        features = self.features(images)
        return self.head(torch.flatten(features, 1))

model = TinyClassifier(len(train_ds.classes))  # CPU example
criterion = nn.CrossEntropyLoss()  # expects logits, not softmax
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)

def accuracy(loader):
    model.eval()
    correct = total = 0
    with torch.inference_mode():
        for images, labels in loader:
            predicted = model(images).argmax(dim=1)
            correct += (predicted == labels).sum().item()
            total += len(labels)
    return correct / total

best_score, best_state = -1.0, None
for epoch in range(10):  # illustrative choice, tune on validation
    model.train()
    loss_sum = 0.0
    for images, labels in train_loader:
        optimizer.zero_grad()        # discard old batch gradients
        logits = model(images)       # forward calculation
        loss = criterion(logits, labels)  # compare with checked labels
        loss.backward()              # derivatives for parameters
        optimizer.step()             # update parameters
        loss_sum += loss.item() * len(labels)
    score = accuracy(val_loader)     # no weight updates here
    print(epoch + 1, loss_sum / len(train_ds), score)
    if score > best_score:
        best_score = score
        best_state = deepcopy(model.state_dict())

model.load_state_dict(best_state)
print("Final held-out test accuracy:", accuracy(test_loader))
torch.save({"state_dict": best_state, "classes": train_ds.classes,
            "image_size": 96}, "my_classifier.pt")

What each part contributes: Dataset supplies pixels and checked labels; the loader makes mini-batches. Conv2d has adjustable filters; ReLU keeps positive responses; pooling changes spatial resolution. The final layer produces unnormalized logits. Cross-entropy compares them with class indices. It already handles the required log-softmax calculation, so the training code does not add softmax first.

Keep the full recipe: save the class order, architecture, preprocessing, weights, data provenance, split definitions, and test results together. The example’s single test accuracy is only a start: inspect per-class errors, rare species, false detector crops, night images, and new sites. Never replace the lab’s released model files with this illustrative checkpoint.

04 · What training actually changes

Make a prediction, measure the error, adjust the weights.

1

Forward pass

A mini-batch of images passes through the current network. Its weights produce scores and, for a detector, location predictions.

2

Loss

A loss function measures disagreement with checked answers. Detection training also penalizes localization errors and handles background examples.

3

Backpropagation

The chain rule calculates how the loss changes with each parameter. These derivatives are gradients, not new labels.

4

Optimizer step

The optimizer uses gradients and a learning rate to change weights. Repeat for many mini-batches; one pass through the training collection is an epoch.

Training can lower the loss by learning useful shapes, textures, and combinations—or misleading shortcuts such as a camera background. A validation collection helps choose settings and a checkpoint. An untouched test collection estimates performance after those choices are fixed. A low training loss alone does not establish field accuracy.

05 · Teach locations as well as labels

A detector learns from boxes that people checked.

The classifier above gives one answer for a whole crop. For detection, a training record also needs one box per visible object: left, top, right, bottom, plus a category. Different detector families construct candidates differently, match them to human annotations during training, and optimize classification and location objectives. Empty frames help teach background behavior.

This outline uses torchvision Faster R-CNN to make a real detector training interface concrete. It is a different architecture from this lab’s YOLOv10 MegaDetector. import torch
from torchvision.models.detection import fasterrcnn_resnet50_fpn

# Explicitly disable both automatic weight downloads.
# This creates an untrained illustrative detector with 4 classes:
# 0 = background; 1 = animal; 2 = person; 3 = vehicle.
detector = fasterrcnn_resnet50_fpn(
    weights=None, weights_backbone=None, num_classes=4
)
# Fine-tuning would instead load a compatible, trusted local checkpoint.
# No checkpoint is fetched or changed by this lesson.
optimizer = torch.optim.SGD(detector.parameters(), lr=0.005,
                            momentum=0.9, weight_decay=0.0005)

# A dataset item has:
# image: float32 tensor [3, H, W], values in [0, 1]
# target = {
#     "boxes": float32 tensor [N, 4] containing x1, y1, x2, y2,
#     "labels": int64 tensor [N] containing category IDs 1..3,
# }
# Human boxes must be valid within that image's width and height.
# An empty image uses boxes shaped [0, 4] and labels shaped [0].
# For variable object counts, create your DataLoader with:
# collate_fn=lambda batch: tuple(zip(*batch))

for epoch in range(10):  # illustration, not a validated recipe
    detector.train()
    for images, targets in train_loader:
        optimizer.zero_grad()
        losses = detector(list(images), list(targets))
        loss = sum(losses.values())
        loss.backward()
        optimizer.step()

# After separately selecting/evaluating a checkpoint:
detector.eval()
with torch.inference_mode():
    prediction = detector([image])[0]
    # prediction contains boxes, labels, and scores.

What is being optimized? Faster R-CNN includes object/background and category losses plus box-regression losses. Other detector architectures use different heads and loss combinations. Box errors and category errors both matter: a high animal score with a badly placed box can make a poor species crop.

Training from scratch versus fine-tuning: the outline starts with initialized weights and needs substantial suitable training data and compute. Fine-tuning starts with compatible pretrained visual features and adjusts some or all weights using the new checked collection. Choose the implementation and license deliberately. A checkpoint from one architecture is not interchangeable with another.

Evaluate localization with a stated overlap rule and one-to-one matching; inspect precision, recall, duplicates, misses, and performance by site and condition. Select a detection threshold using validation evidence, then freeze the decision before final testing. The lab’s 0.30 starting cutoff is a demonstration setting.

How can patterns turn into an animal box?

During detector training, repeated examples connect patterns in many image regions with checked object categories and coordinates. Parameters that help reduce the training objective are updated. At inference, the feature extractor responds to the new scene, and prediction layers turn its feature maps into category scores and location values. Postprocessing expresses accepted candidates in the original image coordinates. The model can respond to learned combinations without a person writing an explicit rule for every fur color or pose.

A score and a rectangle are numerical predictions, not proof that the model understands the animal. New backgrounds, camouflage, motion blur, low detail, unfamiliar species, and unusual viewpoints can cause errors. Raising a cutoff hides weak candidates; it does not improve the pixels, retrain the model, or guarantee that the remaining boxes are correct.

For species classification, the lab takes only actual animal candidates that meet the cutoff, saves the exact crop bytes, and asks a separate trained network to rank its fixed labels. Detector and classifier scores answer different questions. Never multiply them into a claimed probability of a correct species identification.
